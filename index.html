RAGTrace AI

Data quality and observability for RAG chatbots

TypeScript, LangGraph.js, PostgreSQL and pgvector, React, Hono

Most observability tools inspect query-time behavior. RAGTrace AI traces quality from source ingestion through retrieval and generation, using 4 LangGraph.js agent pipelines in a monorepo of 8 npm workspaces.

  • A root-cause tracing agent walks a low-quality answer back through retrieved chunks to source documents and known ingestion defects, and assigns no blame when no document was at fault.
  • A provider-agnostic LLM layer (Gemini, Groq and a deterministic offline fallback) allows failover with no code changes when a free-tier quota runs out.
  • 7 call sites across 5 pipeline stages track token usage, time to first token and inter-token latency. Two REST endpoints report p50, p95 and p99 using Postgres percentile_cont.
  • Every build phase required a runnable verification script, which surfaced and fixed 3 production-blocking bugs: cascading-delete data loss, stale-evidence misattribution and a React key collision.
  • On a 10-question evaluation, 8 of 10 correctly triggered root-cause analysis with zero false attributions, for a total LLM cost of $0.015. The 4-view React and Vite dashboard uses color-vision-deficiency-safe palettes.

Feature Store ML Pipeline and Drift Detection

PySpark, Delta Lake, Feast, Evidently AI, Airflow, Streamlit, scikit-learn

An ML infrastructure pipeline with PySpark feature engineering (lag and 3-month rolling aggregates), versioned Delta Lake storage, a Feast feature store with a SQLite online store, and Airflow orchestration.

During a simulated economic stress event, Evidently AI (Wasserstein and Jensen-Shannon distances) detected 36.7% drift in annual_income and the pipeline quarantined the drifting cohort. Retraining lifted accuracy from 59.3% to 68.2% and AUC-ROC from 0.535 to 0.748. A Streamlit dashboard shows live Feast feature retrieval and embedded drift reports.

These results come from a simulated stress test, not production traffic.

SchemaDrift and SchemaGraph

Real-time schema drift detection and lineage

Python, PostgreSQL, Neo4j, Kafka, FastAPI

A metadata-driven platform that detects schema drift across Kafka, S3, PostgreSQL, Iceberg, Delta Lake and dbt-style pipelines. Schema versions and downstream dependencies live in a graph, so a mutation can be traced to the Bronze, Silver and Gold tables it would break. Malformed data is rescued into a dynamic PostgreSQL structure instead of being dropped.

Validation rules catch schema mutations, null violations and referential problems. Migration SQL is generated by graph traversal, and unsafe schema changes are blocked in a CI-style gate. Interactive lineage and impact views support regression triage and governance.
